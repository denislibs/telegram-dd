# Port report: the messages slice

Branch `port/messages` (stacked on `port/chatlist`, `2fa5f63`), tt baseline `090e38f`. The third UI slice of telegram-dd: an
open chat in the middle column. `MiddleColumn` (the stub is gone), `MiddleHeader` (chat info, header actions), `MessageList`
and `MessageListContent` (date groups, sender groups, unread divider, `NoMessages`, scroll anchoring, history loading in both
directions, jump to the first unread, `focusMessage`, marking as read, the sticky date), `FloatingActionButtons` /
`ScrollDownButton`, `message/Message` for text messages, `ActionMessage` (service messages), and `renderTextWithEntities` in
full (bold, italic, underline, strike, code, pre, links, mentions, hashtags, cashtags, bot commands, spoilers, custom emoji,
blockquote). The composer, the message context menu, selection mode, in-chat search, pinned-bar actions, the right column,
calls, stories and media bodies are FOUNDATION STUBs (below). `pnpm dev:mocked` boots with tt's `default` scenario; the new
`messages` scenario (`#?mockScenario=messages`, generated by `scripts/mock/generateMessagesScenario.ts`) has four chats with
histories of 3, 60, 300 and 400 messages, service messages, an unread boundary and entities.

## Codemod on this slice

77 `.ts` / `.tsx` files, run once from the import commit; 118 `// TODO(codemod)` markers over 45 files (32 files, 42 %, had none), all
resolved by hand (none is left in `src/`). Kinds: `usePrevDuringAnimation` 17, `useSyncEffect` 11, `dependency` 11, `key` 10,
`teactFastList` 5, `ref` 5, `useThrottleForHeavyAnimation` 4, `useShowTransitionDeprecated` 4, a few `getGlobal`, `useForceUpdate`,
`useStateRef` and hook-specific ones. What it got wrong or could not do (fixed by hand; candidates for codemod rules):

- a `//` TODO comment placed inside a JSX child (`MessageListContent`): parse error, turned into `{/* */}`;
- the chat-list list of mistakes recurred: a signal getter passed down became a value; accessor calls missed in templates;
  hooks wrapped in `createMemo`; `createMutationEffect` for an element written at creation; `(props) => ... return renderX()`
  render functions; the discriminated-union narrowing of `createMemo(() => props.message.content.action!)`;
- a keyed single child (`<div key={chatId}>`) became `<Show when keyed>` with a **zero-argument** callback (`{() => ...}`): that
  shape never remounts (engine gap #8); nine call sites in other slices had the same pattern and were changed to `{(_key) => ...}`;
- `useSyncEffect` that reads a prop and writes a ref (`memoFirstUnreadIdRef`, `memoUnreadDividerBeforeIdRef`) became an
  effect that runs after the render; the reads of the first render needed `createMemo` with the ref write inside.

## Deviations from tt worth knowing (all marked `// Deviation:`; 117 comments added in the slice, 27 `TODO(port)`)

- **MessageListContent**: tt maps the groups with nested `map` and `key`; here the groups are entries of a memo (`model`), the
  rows are local `Entries` / `EntryView` / `DateGroupView` components over `<For keyed>`, and every inner list reads its entries from
  `childrenByPath` (a map registered by path) and not from its row's item. The direct form is engine gap #7: frameact reports a
  "potential infinite loop" when an inner keyed list reads from the item of an outer keyed row.
- **MessageList**: the scroll restoration is tt's (snapshot before the DOM update, `requestMeasure` / `requestMutation` after,
  anchor = the second item, `scrollOffset` saved by a debounced `setScrollOffset`, bottom snap class, live tail) as three effects:
  a measure effect for the snapshot, one for the container height, and a forced-reflow effect with 14 dependencies for the
  restore. The unread divider id is a memo with a ref box (tt's `useSyncEffect` + `useRef`).
- **useScrollHooks**: the history triggers (backwards / forwards) are observed **one frame later** (`requestMeasure`). With tt's
  timing the first IntersectionObserver report came while `isReplacingHistoryRef` was still set, was dropped, and an
  IntersectionObserver reports only on change: the list stayed at its first 20 messages and a wheel scroll never loaded more
  (found by the e2e). Behaviour was then compared with tt side by side on open / scroll / switch flows: identical.
- **useFocusMessageListElement**, **usePinnedMessage**, **useContainerHeight**, **useMessageObservers**: accessors in and out, effects
  split by phase; `usePinnedMessage` guards its clamp write so that it cannot loop.
- **messageListReserves**: the probe element is appended with `forceMutation(..., document.body, true)` (stricterdom flagged a
  childList change of the body written in the measure phase).
- **Spoiler** (`common/spoiler/Spoiler.tsx`): the click handler checks `containerId` / revealed state itself (a handler prop is bound
  once), and a spoiler removes only its own registration from `revealByContainerId` (tt dropped the whole container entry when one
  of a message's spoilers unmounted, leaving its siblings unregistered).
- **Composer stub** renders `<div class="Composer" style="height: 3rem; margin-bottom: 1rem">`: tt's outer size, so that the
  message list has tt's height (it was 8 px off without it).
- **Icon** (`common/icons/Icon.tsx`): `aria-hidden="true"` unless there is an `ariaLabel`: decorative icons are hidden from
  assistive technology (a deviation from tt, kept small; `TabList` the same).
- **Chat.tsx** (chat-list slice, found here): `handleClick` read `props.isSelected` after `openChat`, so opening a chat with unread
  messages ran `scrollMessageListToBottom` and the chat opened at the bottom instead of at the first unread. The values are
  captured before the call.
- **MockClient**: `GetDialogFilters` answers `Api.messages.DialogFilters` (it was a bare array: `orderedIds` stayed undefined and the
  chat list showed the placeholder at a 42 px offset in the visual diff), and `getMessagesFrom` answers `[]` for unknown chats.

## `renderTextWithEntities`: what to review (untrusted server content)

The file is the most security-relevant one of the slice; agent A ported it (84 tests in `renderTextWithEntities.test.ts`, a
part of them adversarial: hostile URLs, entity ranges out of bounds, overlaps, deep nesting, huge entity lists).

- **The message-list path builds nodes, never HTML strings**: text is rendered as text nodes and entities as elements; no
  `innerHTML` / `dangerouslySetInnerHTML` is written in `renderTextWithEntities`, `richTextComponents`, `CodeBlock`, `Spoiler` or the
  message components (grepped). tt's _HTML-string mode_ is still there, ported as in tt (`shouldRenderAsHtml`, with
  `renderText(..., ['escape_html', ...])` whose escape is `divEl.innerText = part; divEl.innerHTML` on a detached div): it is reached
  only through `renderMessageSummaryHtml` (the reply / edit preview of the composer, a stub in this slice), never from the message
  list. The remaining `innerHTML` uses in the closure are tt's copy-selection helper (`getSelectionAsFormattedText`, which
  re-parses DOM that is already rendered) and the composer's `cleanHtml` (stub): not reachable with server text in this slice.
- **Links**: tt's `ensureProtocol` / `getDecodedUrl` handling is kept (`util/browser/url.ts`: protocol whitelist `http: https: tg:
ton: mailto: tel:`, everything else gets the `https://` prefix; punycode / mixed-script host checks). `javascript:`, `data:`,
  `vbscript:`, mixed-case and tab-split variants therefore end up as `https://...` hrefs (a relative host, not script). The e2e `a
javascript: link is never rendered as a live href` asserts every `href` in the message and that no dialog opens (it ignores tt's
  own `SafeLink.getDecodedUrl error` log for the hostile URL). Links open with `target="_blank" rel="noopener noreferrer"`.
- **Caps on server-controlled sizes** (marked `// Deviation (untrusted entities)`): at most `MAX_ENTITIES` = 2048 entities are
  used (the text between stays plain), nesting is rendered up to `MAX_NESTING_DEPTH` = 32 levels, entities whose offset / length
  is outside the text, empty or overlapping in a way that cannot nest are dropped by `sanitizeEntities`, and a date entity is
  rendered only when finite and within `MAX_DATE_SECONDS`.
- **Previews**: in a preview the text of every Spoiler range is replaced by braille characters of the same length (all the
  entities are used, not only those under the cap); a 777000 login code stays concealed; the chat-list preview tests are green.
- **Spoiler** reveals on click only (all spoilers of the message together, as in tt); the concealed text is still in the DOM, as in tt
  (`Spoiler__content` is `opacity: 0` and the dots are drawn over it).
- **Code blocks**: tt's `highlightCode` (lowlight: the hast tree is turned into elements by `treeToElements`, no HTML string).
  `highlight.js` is now a direct dependency (`^11.11.2`, BSD-3-Clause, passes `gates:licenses`): tt read the grammars from the
  hoisted `node_modules/highlight.js`, which pnpm does not create (marked as a deviation in `highlightCode.ts`). The grammars are
  lazy chunks (294 KiB raw in the size budget). Unknown languages are rendered as plain text.

## frameact engine gaps found (engine-only; for frameact PRs, not implemented here)

The chat-list report's gaps #1-#6 apply as they were. New:

7. **A false "Potential infinite loop" report for nested keyed lists.** An inner `<For each={row().children} keyed>` inside the
   row of an outer `<For each={groups()} keyed>`, where both sources are rebuilt by one memo: when an effect of an inner row runs
   during the flush that created the outer row, the owner chain is "still dirty after 2 map pulls" and the engine logs
   `[frameact] Potential infinite loop: the owner chain of effect was still dirty ...` (a console error: the strict e2e fails). It
   reproduced in the real `MessageListContent` (a 300-message chat, three levels of lists); a minimal two-level repro with plain
   signals did NOT reproduce it (tried: new `groups()` array with a new group and a changed `children` of an old one), so the
   trigger is the combination with effects that write signals read by the outer list's source. Worked around with
   `childrenByPath` (see Deviations).
8. **`<Show when={x} keyed>{() => ...}` does not remount on a key change when the callback takes no argument.** Minimal repro
   (vitest, jsdom harness of `src/lib/kit/testing/dom`):

   ```tsx
   const [key, setKey] = createSignal('a');
   let created = 0;
   render(
     () => (
       <Show when={key()} keyed>
         {() => {
           created++;
           return <i />;
         }}
       </Show>
     ),
     container(),
   );
   flushSync();
   setKey('b');
   flushSync();
   expect(created).toBe(2); // 1 with the zero-argument callback; 2 with `(k) => { created++; return <i data-k={k} /> }`
   ```

   The codemod emits the zero-argument form for `key={x}` on a single element; nine call sites were changed to `(_key) =>`.
