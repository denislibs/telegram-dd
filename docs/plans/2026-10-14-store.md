# Plan: port the full state layer on the store architecture

Date: 2026-10-14, revised after the architecture review (`docs/reviews/store-architecture-review.md`). Basis:
[`docs/store-architecture.md`](../store-architecture.md) and the prototype on `design/store` (compat layer with the
committed immutable global and the store mirror, verbatim tabs/auth/twoFa/settings files, `MessageListHistoryHandler`,
multitab verbatim, bench, tests).
Reference baseline: tt `090e38f` (porting guide §7.4). Each task ends with `pnpm check` and `pnpm test` green; a task
that touches a screen also runs the browser gates.

## Status

T1–T5 are implemented on `port/state` (report: [`reports/port-state.md`](../reports/port-state.md)); T6 and T7 are open.
Differences from the text below that the implementation found: the import closure of `src/global` reaches UI/teact code
through ~10 modules (localization, notifications, bundles, rich-text rendering, `useAppLayout`), which are FOUNDATION
STUBs until the components land; none of the async handlers behind `forceOnHeavyAnimation`/`forceSyncOnIOs` needed
`ungated()` (all of them are synchronous); `index.tsx` follows tt's boot order (`requestGlobal` → `initGlobal` → `init` →
`establishMultitabRole`), since `switchMultitabRole` needs the tab state that `init` creates.

## Order of work

### T1. Foundation of `src/global` (1–2 days)

1. Import verbatim (one import commit per batch, `port(global): import … from tt@090e38f`): `global/types/*` (already
   in), `initialState.ts` (in), `helpers/**` (replace the `FOUNDATION STUB` barrel; `helpers/messageMedia.ts` has a
   `WeakMap` cache keyed by rich-message object — fine: the object identity is stable now), `selectors/**` (all 24
   files; the barrel `selectors/index.ts` returns to tt's list, drop its allowlist entry), `reducers/**` (all 30; drop
   the barrel's allowlist entry), `src/util` modules they import that are still missing (`areDeepEqual`, `memo`,
   `entities/ids`, `folderManager` — see T4, `notifications`, `sessions`, …).
2. Expected diff against tt for every file in 1: **zero non-import lines**, with one known class of deviation — code
   that mutates a _nested_ object of the global it got from `getGlobal()` instead of returning a new one
   (`actions/api/stories.ts:67,73,110,116`: `global.stories.stateHash = …`). The committed global is immutable and the
   store mirrors `prev → next` by identity, so such a write never reaches the store; rewrite those 4 lines as
   `global = { ...global, stories: { ...global.stories, stateHash } }` with a `// Deviation:` note. Root-level mutations
   (`global.isCacheApiSupported = …` in `init.ts`) need nothing: `getGlobal()` hands out a shallow copy in both modes.
   `src/global/store/mutationGuard.test.ts` already fails the suite on that pattern (oxlint 1.88 has no
   `no-restricted-syntax`). Two more one-line deviations when their files land: `util/memoized.ts` is in (store-proxy
   bypass, N2); `selectors/audioPlayer.ts` gets `if (unwrap(searchParams) !== searchParams)` / `(keys)` guards on its two
   WeakMaps. `gates:diff` enforces the rest.
3. `src/global/index.ts`: already the glue. Add the DEV `window.getGlobal/setGlobal/getActions` exposure (tt's) and the
   `__globalDiffLog` ring buffer behind `DEBUG_MORE`.
4. Tests: keep `src/global/index.test.ts`, `store/apply.test.ts` (the review's C1 probes and the 3000-step property
   test live there); once T1.1 lands, extend the property test to a random sequence of **real** reducers
   (`updateChat`, `addMessages`, `updateTabState`, `replaceThreadParam`, …) and assert the mirror equals the committed
   global by JSON after every step, and that earlier snapshots are untouched.

### T2. Actions (2–3 days, mechanical)

2. The only edits: imports of `addCallback`/`ActionOptions` from `lib/teact/teactn` → `../../index` (`settings.ts`,
   `misc.ts`, `initial.ts`, `api/sync.ts`, `intervals.ts`) and the `addCallback` consumers below. Everything that
   returns a global or calls `setGlobal` stays.
3. `forceOnHeavyAnimation` call sites (35) and `forceSyncOnIOs` (7): no handler changes; for each **async** handler

   `// Deviation:` note. Expected: < 10 sites.
4. `util/init.ts` verbatim (the `'byTabId' in prevGlobal` check works: the store root starts as `{ isInited: false }`).
5. Test: `actions/apiUpdaters/messages.ts` — a `newMessage` update through `getActions().apiUpdate` on a seeded global;

### T3. Cache (0.5 day)

1. Import `cache.ts` verbatim; imports: `addCallback, removeCallback` from `./index`, `getIsHeavyAnimating, onFullyIdle`

### T4. The identity-based consumers (0.5 day): verbatim, plus one hook

The store callbacks receive the committed immutable global (tt's object), so every consumer that compared it with the
previous one works unchanged: `util/folderManager.ts` (`global.chats.byId !== prevGlobal.chatsById`, per-chat `!==`),
`util/emoji/customEmojiManager.ts`, `global/actions/ui/settings.ts` (`switchTheme`, `oldSetLanguage`,
`applyPerformanceSettings`), `ui/misc.ts`, `ui/initial.ts`, `api/sync.ts`, `intervals.ts` (master-role flip),
`shared/sharedStateConnector.ts` (`global.sharedState === lastSharedState`, `deepDiff(lastSharedState, …)`), the
identity caches (`util/memoized` in `selectors/wallet.ts` and `selectors/ui.ts`, `helpers/messageMedia.ts`,
`selectors/audioPlayer.ts`). Tests in `src/global/index.test.ts` (C2) cover the three callback patterns.

Only `hooks/useFolderManager.ts` changes: the hook is ported in place and returns accessors backed by a `createSignal`
set from the folderManager callbacks (teact's `useForceUpdate` has no equivalent).

Components: `useMemo(…, [chat])` and `areShallowEqual(prevChat, chat)` keep working too (an entity is a new object when
it changed, as in tt); they are rewritten to `createMemo` only because `useMemo` does not exist (codemod rule 7).

### T5. Multitab end to end (0.5 day)

`multitab.ts` is tt's code (only the two teact imports changed): `deepDiff(lastBroadcastDiffGlobal, currentGlobal)` of
final states at the idle flush, the `currentGlobal === global` echo check. Remaining: `index.tsx` boot order
(`requestGlobal` → `establishMultitabRole` → `initGlobal`), the `switchMultitabRole`/`initApi` actions (T2), a
two-context browser test in `tests/e2e` (two pages, mocked client) that asserts a chat update in page A appears in page
B and that A's own tab state does not echo. The review's race (a local write superseded by the master before the flush)
is covered by a unit test: the stale value is never sent.

### T6. Components (with the codemod, per screen milestone)

Follow the porting guide §7.1 order (auth → chat list → message list → composer → right column → settings). Per
component the codemod does rules 1–7 of the contract; by hand: the hooks → primitives table, `For`/`Show`, refs, phases.
The `live()` list for T6 (components whose store reads must not wait for an animation in their subtree):
`middle/composer/*` (send state, attachments progress), `common/TypingStatus`, `middle/message/*` upload/download
progress, `calls/*`, `middle/AudioPlayer`, `left/main/ConnectionStatusOverlay`. Everything else parks as tt did.

Per-screen perf check: `tests/perf` `expectNoLongTasks` on "receive 50 messages in the open chat" and "reorder the chat
list 20 times" with the mocked client; compare against `pnpm bench:store` numbers.

### T7. Engine follow-ups (frameact repo, clean-room, PRs)

1. **E3′ `adopt` stops at objects the store already owns.** Needed: an entity or record written by reference that
   points at a big subtree the store already holds but nobody has read through a proxy (a new `globalSearch` record
   with a fresh 5k-result array: 0.5 ms per query today, `pnpm bench:store`) is re-walked by `adopt()` on every write. A
   "store-owned" mark (`WeakSet` set at adopt time, or a node without a proxy) makes `adopt` O(new objects). Until it
   lands, the container rule keeps the common cases cheap (a keystroke that keeps the results array: 5 µs).
2. **E2 `isTracking()`** (DEV only): a warning in `getGlobal()` when it is called inside a tracked computation (the
   caller wanted `useGlobal()`). Never a behaviour switch.
3. **E3 bulk adopt** (low priority): `globalUpdate` of the full master state is ~90 ms for 350k objects; the cache-sized
   start is 9 ms. Only if a start-up trace shows it.

Dropped after the review: `onStoreWrite` (no consumer: the compat layer has no journal, multitab diffs snapshots) and
`reconcile({ arrays: 'value' })`. Bump the submodule with `pnpm framework:update` after each PR.

## What the codemod transforms (summary; exact shapes in store-architecture.md §12)

- `memo(withGlobal<OwnProps>(MAPPER, ACT?)(Comp))` → `Comp`, with `const props = withGlobal<OwnProps>(ownProps, MAPPER,
ACT?)` as the first statement of the body (the type argument may stay: `StateProps` has a default), the destructured
  state/own props rewritten to `props.x`, a destructuring default `({ a = 1 })` to `props.a ?? 1`, and the statement
  named `p` when the body already has a `props` binding.
- `useSelector*` results get `()` at use sites.
- `lib/teact/teactn` imports → `../global`; `memo` import dropped.
- Drops the `<OwnProps>` type argument of `withGlobal` (N4); a destructuring default becomes
  `props.b === undefined ? 1 : props.b`.
- Wraps calls to the 9 `getGlobal()` helpers made from hooks/memos/effects in `trackGlobal(() => …)` (N3); flags
  `useEffect`/`useMemo` deps that list a container prop (N2).
- Flags (comments, no rewrite): `getGlobal()` in JSX/memos; nested mutation of `global` (`global.a.b = …`); async
  handlers called with `forceOnHeavyAnimation`.

## Risks and watch items

- **Nested mutation of the committed global** (`stories.ts`): invisible to the mirror until the next new object on that
  path. The lint rule in T1 and the 4 `// Deviation:` lines close it; a DEV check is impossible without a snapshot.
- **Walk width** on heavy accounts (10k chats, 10k-message threads): `BENCH_CHATS=10000 BENCH_MESSAGES_PER_CHAT=5000
pnpm bench:store` before the message-list milestone. The walk is bounded by the spreads tt already pays (measured
  0.6× the reducer); the opt-in for one reducer is `setState('messages', 'byChatId', chatId, 'byId', reconcile(byId))`.
- **Memory**: the store's container copies cost about +15 % over the tt global (3.7 MB on 24.5 MB for the bench state);
  entities are shared. Watch it on a long session with the mocked client (`tests/perf` leak check).
- **I6 / E3′**: a record that references a large unread subtree pays an `adopt` walk when it is written (0.5 ms per
  `globalSearch` query with 5k results). The container rule keeps it off the keystroke path; the engine fix removes it.
- **`undefined` deletes a container key** (an entity keeps its own `undefined` keys): grep ported code for `in global.`
  / `Object.keys(global.` on slices where a reducer writes `undefined` instead of omitting (expected none that matter).
- **Upstream syncs**: the action layer is byte-identical, so `pnpm gates:upstream` + a plain copy stays the process;
  the standing diffs are `global/index.ts`, `multitab.ts` and `cache.ts` (imports only), the 4 `stories.ts` lines,
  `hooks/useFolderManager.ts` and the component layer.
