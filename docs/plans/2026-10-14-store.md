# Plan: port the full state layer on the store architecture

Date: 2026-10-14. Basis: [`docs/store-architecture.md`](../store-architecture.md) and the prototype on `design/store`
(compat layer, verbatim tabs/auth/twoFa/settings files, `MessageListHistoryHandler`, multitab, bench, tests).
Reference baseline: tt `090e38f` (porting guide §7.4). Each task ends with `pnpm check` and `pnpm test` green; a task
that touches a screen also runs the browser gates.

## Order of work

### T1. Foundation of `src/global` (1–2 days)

1. Import verbatim (one import commit per batch, `port(global): import … from tt@090e38f`): `global/types/*` (already
   in), `initialState.ts` (in), `helpers/**` (replace the `FOUNDATION STUB` barrel; `helpers/messageMedia.ts` has a

   the barrel's allowlist entry), `src/util` modules they import that are still missing (`areDeepEqual`, `memo`,
   `entities/ids`, `folderManager` — see T4, `notifications`, `sessions`, …).
2. Expected diff against tt for every file in 1: **zero non-import lines**. If `tsc` flags something, it is a missing
   util or a type that changed upstream, never a store adaptation. `gates:diff` enforces it.
3. `src/global/index.ts`: already the glue. Add the DEV `window.getGlobal/setGlobal/getActions` exposure (tt's) and the
   `__globalDiffLog` ring buffer behind `DEBUG_MORE`.
4. Tests: keep `src/global/index.test.ts`, `store/apply.test.ts`; add a property test that runs a random sequence of
   **real** reducers (`updateChat`, `addMessages`, `updateTabState`, `replaceThreadParam`, …) against a tt-style
   immutable reference (`deepMerge` of the journal) once T1.1 lands.

### T2. Actions (2–3 days, mechanical)

3. `forceOnHeavyAnimation` call sites (35) and `forceSyncOnIOs` (7): no handler changes; for each **async** handler

5. Test: `actions/apiUpdaters/messages.ts` — a `newMessage` update through `getActions().apiUpdate` on a seeded global;

### T5. Multitab end to end (0.5 day)

Already ported. Remaining: `index.tsx` boot order (`requestGlobal` → `establishMultitabRole` → `initGlobal`), the

### T6. Components (with the codemod, per screen milestone)

Follow the porting guide §7.1 order (auth → chat list → message list → composer → right column → settings). Per
component the codemod does rules 1–7 of the contract; by hand: the hooks → primitives table, `For`/`Show`, refs, phases.
The `live()` list for T6 (components whose store reads must not wait for an animation in their subtree):
`middle/composer/*` (send state, attachments progress), `common/TypingStatus`, `middle/message/*` upload/download
progress, `calls/*`, `middle/AudioPlayer`, `left/main/ConnectionStatusOverlay`. Everything else parks as tt did.

Per-screen perf check: `tests/perf` `expectNoLongTasks` on "receive 50 messages in the open chat" and "reorder the chat
list 20 times" with the mocked client; compare against `pnpm bench:store` numbers.

### T7. Engine follow-ups (frameact repo, clean-room, PRs)

1. `onStoreWrite(hook)` write journal with paths (engine funnel: `setProperty`/`writeArray` + path threading through
   `setState`, `merge`, `produce`, `reconcile`). After it lands: the compat journal subscribes to it, the "no direct
   `setState` outside `src/global/store`" rule goes away, hot paths may use `produce`/`reconcile` freely.
2. `isTracking()` export → DEV warning in `getGlobal()` when called inside a computation.
3. Bulk adopt (`setState(path, adopt(subtree))`) or a `reconcile` option `arrays: 'value'` for the cold start.
4. Optional: `setState(path: PropertyKey[], value)` overload.

Bump the submodule with `pnpm framework:update` after each.

## What the codemod transforms (summary; exact shapes in store-architecture.md §12)

- `memo(withGlobal(MAPPER, ACT?)(Comp))` → `Comp`, with `const props = withGlobal(ownProps, MAPPER, ACT?)` as the first
  statement of the body and the destructured state/own props rewritten to `props.x`.
- `useSelector*` results get `()` at use sites.
- `lib/teact/teactn` imports → `../global`; `memo` import dropped.
- Flags (comments, no rewrite): `getGlobal()` in JSX/memos; identity-keyed `useMemo`; `areShallowEqual` on store
  objects; async handlers called with `forceOnHeavyAnimation`.

## Risks and watch items

- **Aliased id-less objects merged in place** (architecture §1.2): build the DEV alias audit in T1 (idle walk, report
  objects reachable from two paths); run it on the mocked client for every screen milestone.
- **Walk width** on heavy accounts (10k chats, 10k-message threads): run `pnpm bench:store` with `CHATS=10000`,
  `MESSAGES_PER_CHAT=5000` (make them env-configurable) before the message-list milestone; the opt-in is
  `setState('messages', 'byChatId', chatId, 'byId', reconcile(byId))` inside the one reducer that shows up.
- **`undefined` deletes a key**: grep ported code for `in global.` / `Object.keys(global.` on slices where a reducer
  writes `undefined` instead of omitting (expected none that matter).
- **`fromRemote` writes and the cache**: `remoteDiff` is not part of `diff`; the cache does not use diffs (it reads the
  global), so nothing is lost; folderManager merges both.
- **Upstream syncs**: because the action layer is byte-identical, `pnpm gates:upstream` + a plain copy stays the
  process; the only files with a standing diff are `global/index.ts`, `multitab.ts` (12 lines), `cache.ts` (2 imports),
  the identity consumers of T4 and the component layer.
