### What the implementer must not repeat (from the three slices' reviews and reports)

1. **A revealed state is not a render input** (messages I1): `Photo` / `Video` spoiler reveal, `Poll` selection, `TrackRow` seek
   state, `Document` "load allowed" flags must survive a views / reactions / read update (the message object is replaced). Read
   message fields through memos; keep component state in signals the message does not feed.
2. **Stable entries in list models** (messages I2 / perf fix 1): `Album` builds `messages` and `albumLayout` memos; keep identity when
   the ids and ratios did not change, so an album part arriving later re-keys one item, not all. `For` keyed by message id.
3. **In-place store records do not retrigger record-identity effects** (composer M1): `activeDownloads`, `audioPlayer`,
   `mediaViewer`, `poll.results`, `downloads.byChatId` are containers merged in place; `depsOf(() => [props.record])` never fires.
   Depend on fields, or use the slice's `trackRecord` helper when it lands with the composer.
4. **History / observer timing**: observe an IntersectionObserver target in `requestMeasure` (one frame late, like
   `ours middle/hooks/useScrollHooks.ts`), or the first report is dropped while the list is still replacing history.
5. **`<Show keyed>` children take the key** (`{(_key) => …}`), a falsy key renders nothing (`when={{ id }}`).
6. **A placeholder is never the only frameact child of a third-party-owned element** (composer C1): `<video>` children, the ghost
   host, the waveform canvas wrapper, the blurred `<canvas>` next to an `<img>` the browser decodes.
7. **`ManualFor` DOM order and `InfiniteScroll` edges**: not used here; the album is a static `For`.
8. **Lazy rarely-true blocks** (perf fix 2 / item 4): spinners, download overlays, `MediaSpoiler`, the transcription block, the
   "sensitive content" overlay, the pane's rate menu behind one `Show` each; a text message must gain zero media nodes.
9. **Heavy animations**: capture `watchHeavyAnimation` in the body (auth trap), never `getIsHeavyAnimating()` inside an apply as a
   scope check; a store write after an `await` during an animation (a fetch resolving mid-slide) goes through the normal effect
   gating, which is what tt did; `openMediaViewer` / `closeMediaViewer` are `forceOnHeavyAnimation` call sites (port-state report:
   synchronous, no `ungated` needed).
10. **Read after set** (composer H3): `setIsLoadAllowed(true)` then a read of it in the same handler sees the new value.
11. **Phases**: `focus()`, `getBoundingClientRect`, `offsetWidth`, `video.play()` (not a layout read, but a media op: event handler
    or effect apply), canvas `drawImage` of a decoded image (mutate: it is not layout), `scrollIntoView` (measure then mutate).
12. **Boolean / enumerated attributes** (`draggable`, `contenteditable`, `aria-*`) as strings.
13. **The codemod's recurring misses** (chat-list and messages reports): hooks wrapped in `createMemo`, accessor calls missed in
    template literals, `createMutationEffect` for an element written at creation (use `createEffect(c, a, frameMutation)`),
    `(props) => { …; return renderX(); }` render functions run once (`return <>{renderX()}</>`), discriminated-union narrowing lost
    through `createMemo` (`const m = media()` before the `switch`).
14. **`useSyncEffect` that primes a ref before the first render** (messages: `memoFirstUnreadIdRef`) → a memo with the ref write
    inside, not an effect.

  `apiBuilders/common.ts` `buildApiThumbnailFromStripped`; generated by the script from a 40 px JPEG), `DocumentAttributeVideo` (`w`, `h`, `duration`, `roundMessage`, `supportsStreaming`),
  `DocumentAttributeAudio` (`voice`, `duration`, `waveform` 63 bytes, `title`, `performer`), `DocumentAttributeFilename`,
  `DocumentAttributeAnimated` for the GIF, `thumbs` for videos / documents with previews, `MessageMediaWebPage`,
  `MessageMediaPoll` (+ `PollResults`), `MessageMediaGeo` / `GeoLive` / `Venue`, `MessageMediaContact`.
- `upload.GetFile` in `MockClient` returns the **whole** file for every chunk and ignores `offset` / `limit`;
  `lib/gramjs/client/downloadFile.ts` requests 512 KB parts and writes each at its offset, so any asset above one part corrupts.
  The middleware answers `upload.GetFile` itself with `bytes.subarray(offset, offset + limit)`.
- `upload.GetWebFile` (the static map) is unimplemented: the middleware answers it with a generated flat PNG so `Location` reaches
  its loaded state; otherwise the map stays a pulsing `Skeleton` in both apps (masked, and the loaded branch never runs).

  `messages.GetPollResults`, `messages.GetPollVotes` → the recent voters. `messages.TranscribeAudio` → a `TranscribedAudio` text.
  `messages.GetWebPagePreview` is not needed (the preview is in the message).
- Assets in `__data__/` are generated and committed (`scripts/mock/generateMediaAssets.sh`, ffmpeg + ImageMagick, documented and
  deterministic): photos ≤ 80 KB (solid gradients with an id label), a 2 s VP9 / WebM video of solid-colour frames per asset,
  a 2 s opus / ogg voice, a 3 s mp3 with ID3 title, a pdf / zip / svg / html byte string, the 3 MB zip (random bytes from a fixed
  seed). **Codec decision**: Playwright's Chromium has no H.264 / AAC; the test videos are WebM (`mimeType: 'video/webm'`), which
  tt renders as `Video`: `apiBuilders/messageContent.ts` `buildVideo` accepts any `video/*` MIME and
  `apiBuilders/media.ts` `buildApiVideoFromDocument` needs a `DocumentAttributeVideo` plus `self.isWebmSupported` in the API worker
  (set from `IS_WEBM_SUPPORTED` at `initApi`; true in Chromium). Opus and mp3 decode in Chromium.
- The `default` and `messages` scenarios are untouched (their stub-photo album in "Team Chat" now renders real photos: re-check
  `middle-chat-group` at 0 px; its album needs real sizes too, which the `messages` middleware gains).

**The service worker in the gates** (decision D1): the harness blocks service workers (`tests/visual/determinism.ts`,
`serviceWorkers: 'block'`), but `IS_PROGRESSIVE_SUPPORTED` only tests `'serviceWorker' in navigator`, so both apps would request

registers, a video `src` is `./progressive/…`, a Range request is answered by the SW from `callApi('downloadMedia')`, playback

## 7. Security focus list (for the Opus security reviewer)

Untrusted: every media object, web page, poll, location, contact and file name is server / sender controlled.

1. **Dimensions and durations**: `getMediaDimensions`, `calculateAlbumLayout` ratios, `--media-width` / `--media-aspect-ratio`,
   `MediaBadge` duration, `formatMediaDuration`, `TextTimer` / `PlayerTime` / `PlayerSeekLine` with `NaN`, `Infinity`, negative and
   huge values; keep the stubs' clamps (`placeholder.ts`) as a shared `clampMediaDimensions` used by `Photo`, `Video`, `Album`,
   `WebPage` and the viewer; an album of 100 parts; a poll with 100 options (tt has no cap in the view or in `config.ts`: decide a
   render cap with a `// Deviation (untrusted)`, D5).
2. **`blob:` vs remote URLs**: every `src` in the slice must be a `mediaLoader` blob / data URI or a bundled asset; the only remote
   `img-src` is the venue icon (`util/map.ts` `getVenueIconUrl` interpolates `venue.type` raw into the URL: `encodeURIComponent`
   it, a `// Deviation`); `webPage.url` / `displayUrl` only through `SafeLink` / `ensureProtocol`; `prepareMapUrl` from finite
   numbers only; never `window.open` / navigate to a `blob:` of server bytes (same-origin blob = script if HTML / SVG).
3. **Download file names**: `util/download.ts` sets `a.download = document.fileName`: strip C0 / bidi controls (U+202E, U+2066–2069),
   path separators, leading dots, cap the length, keep the extension tt derives (`getDocumentExtension`); the shown name must
   equal the saved name (extension spoofing `report.pdf‮exe.gpj`); `preloadDocumentMedia` and `isHtmlAllowed` in
   `useMediaWithLoadProgress(…, true)` for documents: what MIME the blob gets (`api/gramjs/methods/media.ts`) and that an HTML /
   SVG document is only ever downloaded, never rendered or opened.
4. **MIME sniffing / SVG**: `getDocumentHasPreview` (png / jpeg / gif only); an `image/svg+xml` document gets no `<img>` preview
   (confirm); a `video/webm` with a spoofed `mimeType` reaches `<video>` as a blob (benign); `SUPPORTED_*_CONTENT_TYPES` are upload
   gates, not render gates.
5. **Web page fields**: `siteName`, `title`, `description` (`trimText` cap), `author`, `photo` / `video` / `document` / `audio`
   (all through the same components), `url` (SafeLink + `isSafe` is a **server** flag that skips the confirmation: parity, note),
   quick button deep links (`openTelegramLink` whitelist), `story` (stub), `cachedPage` (not rendered), `stickers`.
6. **Polls**: `question` / `questionEntities`, option `text` / `entities` and `solution` through `renderTextWithEntities` (caps and
   spoiler rules apply), percentages from `votersCount` / `totalVoters` (0, negative, > total), `closeDate` / `closePeriod` timers,
   `recentVoterIds` → `AvatarList`, option media through the media components, `correctAnswers` / `chosenAnswers` as ids only.
7. **Location**: `lat` / `long` finite and in range, `heading` 0–360 into `--direction` (number only), `period`, `accuracyRadius` →
   `getMetersPerPixel` (division by zero at the poles), `venue.title` / `address` / `provider` as text, `type` encoded (2).
8. **Contacts**: `firstName` / `lastName` / `phoneNumber` as text, `formatPhoneNumberWithCode` with garbage, `copyTextToClipboard`
   of the raw number, `userId` sentinel `UNREGISTERED_CONTACT_ID`; the `vcard` string is in the API type but must never be parsed
   or rendered (confirm no path reads it).
9. **Audio / voice**: `title` / `performer` / `fileName` as text and into Media Session metadata (`useTrackMediaMetadata`), `waveform`
   bytes (length ≠ 63, `decodeWaveform` bounds, canvas draw count), transcription text through `renderText`, `duration`.
10. **Video**: `isGif`, `isRound`, `noSound`, `supportsStreaming`, `thumbnail`, `previewPhotoSizes`; `useUnsupportedMedia` notification
    text is ours; `playsinline` / `autoplay` attributes; a hostile `duration` in the viewer's seek line.
11. **CSP** (`ours vite.config.ts` `buildCsp`): `media-src 'self' blob: data:` covers blob and progressive (`./progressive/…` is
    `'self'`, served by the SW); `img-src` adds only the 4sqi host; `worker-src 'self'` (+ `blob:` in dev) covers the media,
    offscreen-canvas and tlottie workers and the SW (`Service-Worker-Allowed: /` header, SW scope `/`); the SW's progressive handler
    talks to the page over `MessageChannel` (no `connect-src` change); `object-src 'none'` stays. Review the SW for a request it would
    proxy from a hostile URL (`progressive.ts` parses its own hash format only).
12. **The mock middleware is not in the production bundle** (`APP_MOCKED_CLIENT` alias only; re-check the scratch production build as
    the messages review did).

## 8. Performance focus list (for the Opus perf reviewer, scenarios `open-media-chat`, `viewer-open`, `viewer-swipe`)

1. **Per-message node cost**: a text message mounts in ~1.4 ms at 4x after the messages perf round (tt ~1.0–1.3) with ~200
   computations; `Photo` adds three show transitions, a spinner, a spoiler, a badge and the appendix background. Target: a photo
   message under +40 nodes over a text message, a video under +60. Lazy `Show` for everything that is false at mount (spinner,
   spoiler, download overlay, upload progress, "sensitive" overlay, GIF / duration badge only when the video has one).
2. **Image decode off the main thread**: `img.decoding="async"` and `decode()` before the `loaded` class flip (tt relies on the
   browser; a `// Deviation` is acceptable if it removes a decode task from the mutate frame); the blur runs in the offscreen worker
   on the 40 px thumb only; never `drawImage` a full photo on the main thread.
3. **Layout from known dimensions**: the frame's `--media-width` / `--media-aspect-ratio` from message data so the swap thumb → full
   image causes zero layout (assert in the e2e with a `PerformanceObserver('layout-shift')` of 0 over the load).
4. **Autoplay limits**: tt plays every intersecting autoplay video; the playing observer's root margin (`useMessageObservers`) is what
   bounds it; count `video` elements with `!paused` while scrolling "Vic Videos" (≤ visible + 1) and the frames dropped against tt.
5. **Album layout**: `calculateAlbumLayout` once per album (memo keyed by the ratios string), items positioned by `style` strings
   computed once; no per-item `withGlobal` mapper beyond tt's.
6. **The viewer**: open / close is tt's ghost animation (transform + opacity on a body-level element, under a heavy-animation
   scope so store updates park: the perf review checks no mapper re-run during the 300 ms); swipe / zoom writes `transform` through
   `requestMutation` from the gesture handler (one write per frame, no layout read after the gesture start); the prev / next slides
   are mounted (tt keeps three), their media loads are `noLoad` until adjacent; `will-change` from tt's scss; frames dropped during
   `viewer-swipe` at tt's level.
7. **Blob and cache**: `mediaLoader` memory cache hit on re-open (no `callApi`), `cacheApi` writes off the critical path (tt: after the
   blob resolves), the download manager's debounce (`GLOBAL_UPDATE_DEBOUNCE`), no `applyGlobal` storm from progress callbacks
   (`loadProgress` is component state, never the global: tt parity).
8. **Audio**: one `<audio>` in the pool, waveform canvas redraw only on progress ticks (tt's `requestAnimationFrame` loop under
   `useAudioPlayback`), the pane's `Transition` not re-created per track.
